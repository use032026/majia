# CleanTrail 产品简报与 MVP PRD

## Intake

| 项目 | 决定或假设 |
| --- | --- |
| 目标用户 | 偶尔需要把供应商、调研、运营或财务表格交给下游系统，但没有桌面数据清洗经验的研究与运营人员 |
| 高频问题 | 空值、重复、首尾空格、列类型混杂和日期格式混杂会让导入失败或分析失真；手工修复缺少可追溯凭证 |
| 使用情境与频率 | 在手机或平板收到 CSV、TSV 或 Excel 后、交付前，每周到每月使用 |
| 首发语言与区域 | 简体中文、英文；具体 App Store 国家或地区尚未确定 |
| 平台 | Flutter；MVP 生成 iOS 与 Android 目标，App Store 预检单独评估 iOS |
| 工作名 | CleanTrail / 清迹；尚未完成商标与商店名称可用性检索 |
| iOS 标识 | `com.example.cleantrail` 仅为占位符，上架前必须替换 |
| 最低 iOS | iOS 13.0；最终产品决策待真机矩阵验证 |
| 变现 | 用户未指定；MVP 假设免费且无 IAP，任何付费方案都需要重新审核 |
| 账号与后台 | 无账号、无后台、无云同步 |

| 外部 SDK | 无分析、广告或崩溃上传 SDK；只使用表格解析、字符编码、系统文件选择、应用目录和系统分享相关依赖 |

## 产品论点

- 目标用户：需要在移动设备上把小型表格安全交付给别人或另一个系统的非专业数据用户。
- 昂贵问题：隐藏的空值、重复与格式问题常在下游导入或分析时才暴露，返工且无法说明改过什么。
- 产品承诺：不上传数据，用一个可解释、可撤销的修复队列把表格变为可交付数据。
- 核心闭环：导入并确认格式/编码/工作表或打开样例 → 本机检查 → 逐项查看影响 → 确认修复或保留 → 自动复检 → 预览 → 导出清洗 CSV 与审计凭证。
- 耐久输出：不覆盖源文件的清洗 CSV，以及不嵌入完整源数据的 Markdown 质量报告。

## 非目标

- 不做通用电子表格、桌面级批量表达式、数据库或在线协作。
- 不做 ChartPrism 式图表类型与主题库；图表只用于修复结果验证。
- 不做 OCR、AI 自动决策、URL 导入、账号、iCloud、订阅、广告或遥测。
- 不承诺统计因果推断，也不自动猜测缺失值含义。

## 信息架构与状态

1. 空工作台：产品边界、隐私承诺、系统文件导入和可重复的内置样例。
2. 导入确认：文本文件显示自动识别的 CSV/TSV 与 UTF-8/GBK，可手动调整；XLSX 显示工作表选择。
3. 项目总览：文件名、行列数、未处理数、质量分、已修复与保留数。
4. 修复队列：按问题逐项进入底部详情；显示行、列、当前值和建议。
5. 决策：采用建议、输入替换值、删除重复行或保留原样。
6. 自动复检：每次决定后重新运行全部规则，新问题继续留在队列。
7. 预览：首个数值列折线校验和前五行表格；不是可视化制作器。
8. 导出：已完成复核时交付 `_clean.csv`；仍有未决问题时显式警告并交付 `_draft.csv`，同时附摘要型 Markdown 报告。
9. 恢复与退出：一个项目工作副本及最近有效备份保存在 App 私有目录；可撤销本次会话最近修改，也可明确移除本地项目。

覆盖状态：空、载入中、用户取消、编码失败、文本结构失败、Excel 解析/工作表失败、规模超限、恢复已有项目、未处理问题、全部已有决定、导出失败和删除确认。MVP 无网络加载状态，因为核心路径没有网络依赖。

## 领域模型与数据所有权

- `DataProject`：项目元数据、表头、原始快照、工作行、问题与审计动作。
- `DataRecord`：稳定行 ID 与单元格字符串；删除工作行不改变原始快照。
- `DataIssue`：问题类型、稳定行 ID、列、原值、建议和 open/fixed/ignored 状态。
- `AuditAction`：动作类型、行 ID、列名、时间；导出报告刻意不写入完整行值。
- `ProjectStore`：只拥有 App 私有目录中的一个 JSON 工作副本与原子写入恢复备份。
- 原始表格：始终由系统 Files 提供者拥有，CleanTrail 不原位写回。

## 功能需求与验收标准

| ID | 需求 | 验收标准 | 证据层 |
| --- | --- | --- | --- |
| FR-01 | 导入表格 | 支持 CSV/TSV/TXT 的 UTF-8/GBK 识别与手动选择，以及 XLSX 工作表选择；用户可取消且已有项目不变；拒绝空文件、无数据行、无效结构、超过 5 MB/10,000 行/100 列/100,000 单元格/500 问题 | 单元测试 + 模拟器/真机 |
| FR-02 | 原始数据保护 | 所有修复只改变工作副本；原始快照与源文件不变 | 单元测试 |
| FR-03 | 数据质量规则 | 检出缺失、规范化后重复、首尾空格、数字列混合类型、日期列无效或混合格式 | 单元测试 |
| FR-04 | 用户确认 | 每项可采用建议/输入值/删除重复行/保留原样，不做静默批量修复 | Widget + 模拟器 |
| FR-05 | 自动复检 | 每次决定后对工作副本重新运行规则；无效替换不得虚假关闭问题 | 单元测试 |
| FR-06 | 撤销 | 会话中可逐步撤销，恢复后的版本同步写入本地存储 | 控制器测试 + 模拟器 |
| FR-07 | 本地恢复与清除 | 重启后恢复一个项目；清除需确认并说明不影响原始文件 | 控制器/静态 + 真机待补 |
| FR-08 | 验证预览 | 显示前五行和首个含至少两个数值的列；没有可用列时显示明确空态 | Widget + 模拟器 |
| FR-09 | 双文件导出 | 输出 clean 或明确标记的 draft CSV 与中/英文报告；iPad 分享提供 popover origin；报告不嵌入完整源行；临时文件独立清理并在启动时重试 | 单元/控制器 + 真机待补 |
| FR-10 | 本地化 | UI 与报告支持简体中文和英文，切换不丢项目状态 | Widget + 模拟器 |
| FR-11 | 可访问与自适应 | 语义化质量分和图表、44pt 以上主交互、系统深色模式、可滚动长内容、横向表格 | 静态 + 模拟器；VoiceOver/Dynamic Type 待补 |
| FR-12 | 隐私边界 | App 内说明本机存储与主动分享边界；无登录、分析、广告或网络上传代码 | 静态 + 归档依赖检查 |

## 视觉方向

视觉采用“纸张上的校验轨迹”：暖纸色背景、深青墨色、琥珀色确认轨迹，卡片圆角和内容密度围绕检查任务。原创图标由网格与琥珀色校验路径构成。布局没有复用竞品截图、品牌、文案、资产或以图表库为中心的层级。

## 已知限制

- 当前支持 CSV、TSV、TXT 和 XLSX；文本编码限 UTF-8 与 GBK，不支持 XLS、JSON、复杂工作簿公式求值和自定义检查规则。
- 日期启发式只识别四种明确格式，斜线日/月顺序可能有地域歧义。
- 质量分按当前仍存在的 open 或 kept 缺陷占单元格比例计算；它是启发式提示，不是统计质量认证。
- 会话撤销栈不跨重启保留；项目数据与审计动作会跨重启保留。
- 文件仍以一次性内存读取和解析；因此组合上限为 5 MB、10,000 行、100 列、100,000 单元格、500 个问题，尤其是压缩后的 XLSX 仍需真机性能测试确认最终值。
