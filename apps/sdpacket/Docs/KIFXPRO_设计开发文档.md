## 1. 产品摘要

本产品是一款面向家庭搬家、临时仓储和小型办公搬迁场景的箱体登记与定位工具。

它不负责提供搬家攻略、物流运输或搬家公司撮合服务，而是为每个现实纸箱建立一张“数字身份证”，帮助用户回答三个具体问题：

1. 某件物品被装进了哪个箱子？
2. 某个箱子应该搬到哪个房间、当前处于什么状态？
3. 所有箱子是否已经装车、到达和拆箱，是否存在遗漏？

产品核心不是二维码技术，而是“快速建立数字记录并与现实箱体对应”。二维码是可选的识别加速方式；没有打印机、没有网络时，用户仍可通过手写编号或便利贴完成全部核心流程。

产品主路径为：

```text
拍照 / 语音 / 手动输入
        ↓
自动生成箱号和箱子草稿
        ↓
快速确认或修改备注
        ↓
提醒用户标记现实箱体
        ↓
打印二维码 / 手写编号 / 粘贴便利贴
        ↓
搬运扫码、状态追踪、物品搜索和拆箱归档
```

## 2. 背景与核心问题

### 2.1 现实问题

普通搬家通常依赖纸箱上的手写文字、手机相册、备忘录或聊天记录。箱子数量增加后容易出现：

- 照片与纸箱无法对应。
- 用户记得装过某件物品，却不知道在哪一箱。
- 箱体编号重复、遗漏或难以辨认。
- 搬运人员不知道箱子应该放到哪个房间。
- 到达后无法快速确认是否少了一箱。
- 未拆箱物品长期存放后难以查找。
- 登记过程太慢，用户在搬家压力下容易放弃使用。

### 2.2 最需要解决的痛点

本产品首先解决“录入麻烦”，其次才是扫码效率。

如果用户需要逐件输入物品、逐项选择复杂属性，产品将很难被持续使用。因此 MVP 必须允许用户只拍一张照片或说一句话，就能生成一个可用箱子记录；房间、标签和结构化物品均为可选增强信息，不得阻塞保存。

### 2.3 产品价值

AI 可以生成搬家建议、识别照片或整理文字，但通用 AI 不会天然维护现实纸箱的编号、位置、搬运状态和长期记录。本产品的价值来自以下闭环：

```text
现实箱体 ←→ 可验证标识 ←→ 本地数字记录 ←→ 搜索和状态追踪
```

## 3. 产品定位

### 3.1 一句话定位

通过拍照或语音，在十几秒内登记一个纸箱，并在搬家过程中随时找到物品、确认箱体位置和追踪搬运状态。

### 3.2 目标用户

- 一次搬运约 20 箱以上的家庭。
- 经常租房、跨城市或跨境搬家的人群。
- 有地下室、迷你仓、储物间或长期未拆箱物品的家庭。
- 需要多人协作整理物品的家庭。
- 专业整理师。
- 小型办公室或工作室搬迁人员。

### 3.3 不适用人群

- 只有少量行李、无需查找物品的轻量搬家用户。
- 需要实时车辆定位或专业物流调度的企业。
- 需要仓库进销存、采购和财务能力的大型组织。

### 3.4 产品目标

- 典型单箱登记流程控制在十几秒内。
- 无账号、无网络、无打印机时仍可完成核心流程。
- 用户可以通过物品名称、箱号、房间或标签快速找到箱子。
- 搬家结束时可以识别未到达或未拆箱的箱子。
- 数字记录必须持续提醒用户完成现实箱体标记。
- 产品全功能免费，不设置订阅或付费墙。

### 3.5 非目标

MVP 不包含：

- 搬家公司撮合、报价和支付。
- 物流车辆实时定位。
- 社区、聊天或用户生成内容平台。
- 强制账号注册和云端后台。
- 必须联网的第三方 AI 服务。
- 自动判定贵重物品价值或提供保险服务。
- 企业级仓库库存、订单和财务系统。
- 广告 SDK、订阅和应用内付费。

## 4. 产品设计原则

### 4.1 快速登记优先

- 自动生成箱号，用户不必先输入名称。
- 备注可直接保存整段文字，不强迫拆分为多个结构化物品。
- 房间、标签、优先级等信息均可稍后补充。
- 拍照和语音完成后立即产生草稿，识别失败不得导致数据丢失。
- 批量登记必须提供“保存并继续”操作，减少页面往返。

### 4.2 实体与数字记录一致

- 每次新建箱子后都要提示用户标记现实箱体。
- 纸箱编号在同一个项目内必须唯一。
- 箱号删除后默认不自动复用，避免旧标签与新记录冲突。
- 二维码中不写入完整物品清单，避免隐私泄露和修改后数据过期。
- “二维码已生成”不等于“箱体已标记”，两种状态必须区分。

### 4.3 离线优先

- 项目、箱子、照片、备注、搜索、二维码生成和 PDF 导出均应离线工作。
- 没有打印机时提供手写编号和便利贴方案。
- 语音离线识别取决于设备和语言支持；不可用时必须回退到手动备注，不能阻塞建箱。

### 4.4 最小权限

- 仅在用户主动拍照、选择照片或使用语音时请求对应权限。
- 优先使用系统照片选择器，避免请求整个照片库权限。
- 不要求定位、通讯录、追踪或通知权限才能使用基础功能。

### 4.5 免费且克制

- 全部核心功能免费。
- 无订阅、无项目数量限制、无二维码导出限制。
- MVP 不新增广告和无关第三方依赖。

## 6. 核心对象与状态

### 6.1 项目 Project

一个项目代表一次搬家、一次办公室迁移或一个长期储物空间。

主要字段：

| 字段 | 说明 |
|---|---|
| id | 本地唯一标识 |
| name | 项目名称 |
| moveDate | 搬家日期，可选 |
| origin | 原位置，可选 |
| destination | 目标位置，可选 |
| boxPrefix | 箱号前缀，默认 `C` |
| nextSequence | 下一个可分配序号 |
| createdAt / updatedAt | 创建和更新时间 |
| archivedAt | 归档时间，可选 |

### 6.2 箱子 BoxRecord

主要字段：

| 字段 | 说明 |
|---|---|
| id | 本地 UUID |
| projectId | 所属项目 |
| shortCode | 人可读箱号，例如 `C-009` |
| title | 可选标题，例如“咖啡用品” |
| destinationRoom | 目的房间 |
| currentLocation | 当前存放位置 |
| memo | 原始或编辑后的备注全文 |
| tags | 易碎、贵重、怕潮、优先拆箱等 |
| priority | 普通或优先 |
| moveStatus | 搬运状态 |
| physicalMarkStatus | 待标记或已确认标记 |
| physicalMarkMethod | 二维码、手写、便利贴或其他 |
| labelExportedAt | 标签最后导出时间，可选 |
| physicalMarkedAt | 用户确认现实标记时间，可选 |
| createdAt / updatedAt | 创建和更新时间 |

### 6.3 搬运状态 MoveStatus

核心状态按顺序设置为：

```text
草稿 → 已打包 → 已装车 → 已到达 → 已拆箱
```

异常情况使用独立标记，不强行替换主状态：

- 疑似遗漏
- 箱体损坏
- 内容物损坏

### 6.4 实体标记状态 PhysicalMarkStatus

```text
待标记 → 已确认标记
```

标记方式包括：

- 二维码标签已粘贴
- 已手写编号
- 已粘贴便利贴
- 其他

“已导出标签”只能记录导出行为，不能自动视为箱体已完成标记。

### 6.5 箱内物品 BoxItem

结构化物品为可选能力，不得成为建箱的必填步骤。

| 字段 | 说明 |
|---|---|
| id | 本地唯一标识 |
| boxId | 所属箱子 |
| name | 物品名称 |
| quantity | 数量，可选 |
| note | 补充备注 |
| createdAt / updatedAt | 创建和更新时间 |

搜索必须同时覆盖结构化物品和箱子备注。因此即使用户只保存一段语音转写，仍然可以搜索其中的关键词。

### 6.6 照片 BoxPhoto

- 默认保存在应用本地目录。
- 数据库存储文件引用和缩略图信息，不直接存储大图二进制。
- 支持一张主要照片和多张补充照片。
- 批量拍照登记时默认“一张照片生成一个箱子草稿”。

## 7. 详细功能设计

### 7.1 项目管理

用户可以：

- 创建、编辑、归档和恢复项目。
- 查看箱子总数及各状态数量。
- 设置箱号前缀和起始序号。
- 查看待实体标记、未到达和未拆箱的箱子。
- 导出项目清单和本地备份。

新用户应提供一个可删除的示例项目，帮助理解流程，但不得强制保留示例数据。

### 7.2 快速登记入口

项目详情页突出三个入口：

1. 批量拍照。
2. 语音登记。
3. 手动登记。

默认箱号自动生成。用户完成拍照或语音后，可以直接接受默认箱号并保存，不要求先填写房间和物品。

### 7.3 批量拍照登记

#### 7.3.1 输入

- 支持连续调用相机拍摄多张照片。
- 支持从系统照片选择器一次选择多张照片。
- 初版建议每批最多处理 30 张，具体上限应根据设备性能验证后配置。

#### 7.3.2 草稿生成

- 默认一张照片对应一个箱子草稿。
- 按项目编号规则连续生成箱号。
- 创建草稿后立即持久化，防止中途退出丢失。
- 用户可以删除误拍照片或删除对应草稿。
- 删除箱子后，其编号默认不自动分配给后续箱子。

#### 7.3.3 连续编辑

编辑页建议显示：

```text
3 / 8

[箱体照片]
箱号：C-003
目的房间：厨房（可选）
备注：咖啡机、杯子、滤纸（可选）
标签：易碎、优先拆箱（可选）

[保存并编辑下一箱]
```

支持：

- 修改箱号并校验项目内重复。
- “保存并下一箱”。
- 将同一房间或标签批量应用到选中箱子。
- 跳过暂时无法确认的草稿。
- 中途退出后继续未完成批次。

#### 7.3.4 实体标记强提醒

单箱拍照登记完成后，显示单箱提醒。

批量登记不应为每个箱子连续弹出阻塞弹窗，以免破坏快速录入；应在整批编辑完成后统一显示不可忽略的确认页：

> 已创建 8 个箱子记录。请立即在现实箱体上分别标记 C-001 至 C-008，避免数字记录与纸箱错位。

可选操作：

- 打印二维码标签。
- 查看手写编号清单。
- 稍后处理，保留为“待标记”。
- 逐项确认已完成实体标记。

### 7.4 语音登记

#### 7.4.1 基本规则

- 一次录音默认生成一个箱子草稿。
- 结束录音后立即分配默认箱号。
- 完整语音转写保存为箱子备注。
- 可根据关键词建议房间、标签或结构化物品，但建议结果必须由用户确认。
- 识别或解析失败时仍然保留草稿和可获得的原始文本。
- 默认不长期保存原始音频，只保存用户确认后的文字；如未来需要保存音频，必须单独设计隐私说明和存储策略。

示例：

```text
用户语音：
“厨房箱，里面是咖啡机、两个杯子、滤纸和电源线，易碎，优先拆。”

自动草稿：
箱号：C-009
目的房间：厨房
备注：咖啡机、两个杯子、滤纸和电源线
标签：易碎、优先拆箱
```

#### 7.4.2 权限与降级

- 仅在用户点击语音入口后请求麦克风和语音识别权限。
- 用户拒绝权限时，展示手动备注入口。
- 设备或语言不支持离线识别时，应说明语音能力可能暂不可用，并允许立即改用文字登记。
- 不得因为语音不可用而影响项目、拍照、手动建箱、搜索和二维码能力。

#### 7.4.3 保存后提醒

语音草稿保存后提示：

> 数字记录 C-009 已创建。请在对应纸箱上手写 C-009、粘贴便利贴或打印标签。

### 7.5 手动登记

手动登记作为可靠兜底，必填项仅为自动生成的箱号。用户可以直接保存空白箱子，稍后补充：

- 标题或备注。
- 目的房间。
- 当前存放位置。
- 标签和优先级。
- 结构化物品。
- 箱体照片。

### 7.6 二维码与打印

#### 7.6.1 二维码数据

二维码仅包含用于本地解析的版本、项目标识、箱子标识和可读箱号，不包含完整物品清单、地址或用户隐私信息。

建议载荷结构：

```text
MOVEBOX|v=1|project=<project-id>|box=<box-id>|code=C-009
```

载荷必须带版本号，为后续格式升级保留兼容能力。

#### 7.6.2 标签内容

二维码之外必须显示肉眼可读信息：

```text
C-009
厨房｜易碎｜优先拆箱

[二维码]

请放置到：厨房
```

即使二维码污损或无法扫描，用户仍可通过箱号搜索。

#### 7.6.3 导出格式

MVP 支持：

- 单个标签高清 PNG。
- 单个标签 PDF。
- 多标签自动排版的 A4 PDF。
- 系统分享面板。
- 系统打印面板。

打印要求：

- 黑色码点、白色背景，避免透明和渐变背景。
- 保留标准留白区。
- 缩放时使用整数倍或无插值方式，避免二维码边缘模糊。
- PDF 优先使用矢量或高分辨率渲染。
- 标签必须在常见家用打印机和黑白打印条件下可识别。

#### 7.6.4 无打印条件兜底

用户选择“暂不打印”或关闭打印页面时，提供明确说明：

> 暂时没有打印机也可以继续使用。请将箱号 C-009 直接写在纸箱明显位置，或写在便利贴上粘贴到箱体。

页面提供：

- 高对比度放大显示箱号。
- 复制箱号。
- 查看全部待标记箱号。
- 标记为“已手写”。
- 标记为“已贴便利贴”。
- 稍后打印。

### 7.7 扫码与箱体操作

用户从 App 内扫描二维码后进入对应箱子详情页，并可快速执行：

- 查看箱内备注和物品。
- 查看目的房间和当前存放位置。
- 标记已打包、已装车、已到达或已拆箱。
- 修改当前存放位置。
- 记录箱体或内容物损坏。
- 确认二维码标签已粘贴。

无法解析的二维码不得导致崩溃；应显示“这不是本应用支持的箱子标签”，并允许手动搜索箱号。

### 7.8 搜索与定位

搜索范围包括：

- 箱号。
- 箱子标题。
- 箱子备注全文。
- 结构化物品名称。
- 目的房间。
- 当前存放位置。
- 标签。
- 搬运状态。

搜索结果至少显示：

```text
C-009｜厨房｜已到达
咖啡机、杯子、滤纸和电源线
当前状态：尚未拆箱
```

搜索必须离线可用。对中文备注应支持基础的包含匹配；分词、模糊搜索和同义词扩展可作为后续优化，不应阻塞 MVP。

### 7.9 搬家进度

项目详情页展示：

```text
箱子总数：30
待实体标记：2
已打包：30
已装车：30
已到达：29
已拆箱：12
疑似遗漏：1
```

重点入口：

- 查看未到达箱子。
- 查看优先但尚未拆箱的箱子。
- 查看仍未完成实体标记的箱子。

### 7.10 长期储物

搬家完成后，用户可以归档项目，也可以继续为未拆箱物品记录位置，例如：

```text
C-021
当前位置：地下室 / 货架 B / 第二层
内容：冬季衣物
```

此能力提升产品在搬家结束后的持续价值，但不扩展为完整仓储系统。

### 7.11 导出、备份与恢复

MVP 至少支持：

- 项目箱子清单 PDF。
- 项目数据 CSV。
- 标签 PDF。
- 包含结构化数据和本地照片引用的应用备份包。
- 从本地文件恢复备份。

恢复时必须处理：

- 项目 ID 冲突。
- 箱号重复。
- 照片文件缺失。
- 旧版本数据字段缺失。

恢复失败不得覆盖现有数据；应先验证备份完整性，再执行导入。

## 9. 交互与可用性要求

### 9.1 十几秒登记目标

典型单箱快速路径中，从照片拍摄完成或语音转写完成，到箱子草稿保存，不应超过三个必须操作步骤：

1. 接受或修改自动箱号。
2. 可选修改备注。
3. 保存。

“十几秒”作为可用性目标，通过真实用户任务测试验证，不以网络请求时间为前提，也不包含用户实际说话或拍照所需时间。

### 9.2 减少强制输入

- 房间不是必填项。
- 结构化物品不是必填项。
- 不要求先创建标签体系。
- 不要求先打印二维码。
- 不要求注册账号。

### 9.3 防错

- 项目内箱号重复时即时提示并阻止保存。
- 用户修改箱号后，如标签已经导出，提示旧标签可能失效并建议重新打印或修改实体标记。
- 删除带二维码的箱子时提示现实标签可能仍然存在。
- 批量流程中退出时自动保留草稿。
- 批量确认实体标记时必须显示照片缩略图和箱号，降低贴错风险。

### 9.4 无障碍与本地化

- 支持动态字体和 VoiceOver。
- 箱号、状态和主要操作不能仅靠颜色区分。
- 二维码标签上的文字保证黑白打印可读。
- 所有用户可见文案使用本地化资源，不直接写死在代码中。
- 首版可优先支持简体中文，但数据模型和 UI 应预留英文长度。

## 10. iOS 技术方案

### 10.1 技术原则

- 若为新项目，推荐 SwiftUI + SwiftData 或 Core Data。
- 若已有工程，应复用现有 UI 和持久化技术，不为本需求进行架构迁移。
- 使用 Apple 系统框架完成照片、语音、二维码、PDF 和打印能力。
- 不为本次需求新增第三方 SDK。
- 数据默认保存在本机，不依赖后台服务。

### 10.2 推荐系统能力

| 能力 | 推荐实现 |
|---|---|
| 多选照片 | PhotosPicker / PhotosUI |
| 相机拍摄 | 系统相机或现有相机模块 |
| 语音转文字 | Speech + AVFoundation |
| 二维码生成 | Core Image `CIQRCodeGenerator` |
| 二维码扫描 | VisionKit、AVFoundation 或现有扫描模块 |
| PDF 生成 | UIGraphicsPDFRenderer / PDFKit |
| 打印 | UIPrintInteractionController |
| 文件导出 | 系统分享面板与文件选择器 |
| 本地搜索 | 持久化层查询 + 备注全文包含匹配 |

具体框架选择应以现有工程最低系统版本和已实现模块为准。

### 10.4 数据一致性

- 编号分配和草稿保存应在同一事务中完成。
- 批量创建时逐项持久化，避免最后一步失败导致整批丢失。
- QR 使用稳定 UUID，不以可修改箱号作为唯一查找依据。
- 用户修改箱号不应导致二维码失效；二维码解析后展示当前箱号。
- 删除项目时应明确处理关联照片和备份，避免孤立文件。

### 10.5 图片存储

- 保存适合查看和导出的压缩版本，不默认长期保留超大原图。
- 生成缩略图用于列表，避免滚动时加载完整图片。
- 图片文件名使用 UUID，不使用箱号，避免修改箱号后移动文件。
- 删除箱子时清理对应本地图片，但须确认没有被其他记录引用。

### 10.6 语音识别

- 请求权限前显示用途说明。
- 优先使用设备支持的本地识别能力。
- 不宣称所有设备和语言均可完全离线识别。
- 识别过程中保存临时状态；失败时允许用户复制已有转写或切换手动输入。
- 自动解析出的房间、标签和物品均视为建议，不直接覆盖用户内容。

### 10.7 二维码渲染

- 使用稳定字符串编码和固定版本头。
- 默认使用中等级别容错，最终参数以实际打印扫描测试为准。
- 放大二维码时关闭平滑插值，确保边缘清晰。
- 标签 PDF 中同时绘制可读箱号，二维码不是唯一识别手段。

## 11. 隐私与权限设计

### 11.1 数据边界

- 项目、箱子、备注、照片和物品清单默认仅保存在设备本地。
- MVP 不上传第三方服务器。
- MVP 不接入第三方 AI。
- MVP 不进行广告追踪或用户画像。
- QR 不包含地址、照片和完整物品内容。

### 11.2 权限请求

| 权限 | 触发时机 | 拒绝后的行为 |
|---|---|---|
| 相机 | 用户主动拍照或扫码 | 保留照片选择、手动登记和箱号搜索 |
| 照片 | 用户主动选择图片 | 保留相机和手动登记 |
| 麦克风 | 用户主动使用语音登记 | 切换到文字备注 |
| 语音识别 | 用户主动使用语音登记 | 切换到文字备注 |
| 通知 | 未来增加搬家提醒时单独请求 | 不影响任何基础功能 |

应用内需要提供清晰的隐私说明，并在 App Store Connect 中如实填写数据收集标签。

## 14. 验收标准

### 14.1 批量照片登记

1. 用户可以一次拍摄或选择多张照片。
2. 每张照片默认生成一个带连续箱号的草稿。
3. 用户可以逐张修改箱号和备注。
4. 用户可以删除误拍照片而不影响其他草稿。
5. 中途退出后可以恢复未完成批次。
6. 完成整批编辑后出现实体标记强提醒。
7. 已保存箱子立即可搜索、编辑和导出。

### 14.2 语音登记

1. 一次语音默认生成一个箱子草稿。
2. 转写内容保存为备忘录，并开放编辑。
3. 识别错误可被用户修正。
4. 解析失败不会丢失草稿。
5. 权限被拒绝时可以立即切换文字登记。
6. 保存后出现实体箱体标记提醒。

### 14.3 二维码与打印

1. 可以导出单个高清二维码标签。
2. 可以批量生成 A4 PDF。
3. 标签同时包含二维码和可读箱号。
4. 扫描后进入正确箱子记录。
5. 修改可读箱号后，基于稳定 UUID 的原二维码仍能找到该箱子。
6. 无打印条件时显示手写和便利贴方案。
7. “已导出”不会自动变成“已完成实体标记”。

### 14.4 搜索和状态

1. 箱号、备注、物品、房间和标签均可搜索。
2. 搜索离线可用。
3. 扫码后可以更新搬运状态。
4. 项目统计与箱子状态一致。
5. 可以明确列出未到达、未拆箱和待实体标记箱子。

### 14.5 免费与隐私

1. 新安装用户不会遇到订阅、试用或付费墙。
2. 所有核心功能均可免费使用。
3. 飞行模式下仍可完成手动或照片登记、搜索、二维码生成和 PDF 导出。
4. 用户拒绝非必要权限后仍可使用基础功能。
5. QR 内容不包含完整物品清单和地址。

## 15. 测试与验证计划

### 15.1 功能测试

- 创建、编辑、归档和恢复项目。
- 连续创建、删除和修改箱号，验证不重复和不意外复用。
- 分别测试 1 张、10 张和建议上限数量的批量照片。
- 批量编辑途中强制退出并恢复。
- 语音识别成功、部分成功、失败和权限拒绝。
- 单个和批量二维码生成、分享和打印。
- 手写、便利贴和二维码三种实体标记方式。
- 扫码更新各搬运状态。
- 搜索中文备注、箱号、房间和结构化物品。
- 导出、备份、恢复和失败回滚。

### 15.2 离线测试

在飞行模式下验证：

- 创建和编辑项目。
- 手动及照片批量登记。
- 本地搜索。
- 二维码生成和扫描。
- PDF 标签导出。
- 状态更新和进度统计。
- 语音无法使用时的手动降级路径。

### 15.3 打印与扫描测试

- A4 黑白打印。
- A4 彩色打印。
- 不同比例缩放打印。
- 二维码轻微折痕、胶带反光和普通室内光线。
- 标签被裁剪后仍保留完整留白区。
- 二维码无法扫描时，使用可读箱号完成搜索。

### 15.4 可用性测试

让首次使用者完成以下任务：

1. 拍摄并登记一个箱子。
2. 用语音登记一个箱子。
3. 在无打印机条件下完成现实标记。
4. 搜索某件物品并找到对应箱子。
5. 将一个箱子从“已装车”更新为“已到达”。

目标：用户不阅读长说明也能理解二维码并非必需；典型单箱登记在拍照或转写完成后，十几秒内保存成功。

### 15.5 回归测试

如果此功能加入已经上线的产品，必须验证：

- 旧项目、旧箱子、旧照片和旧二维码仍能读取。
- 原有搜索结果不减少。
- 原有搬运状态和统计不改变。
- 原有 PDF、CSV 和备份仍可导出。
- 不修改现有账号、同步或其他业务逻辑。
- 数据迁移失败时不会破坏用户原有数据。

## 16. 本次需求改动点说明

相对于最初“二维码搬家清单”的设想，本次产品方案完成以下调整：

1. 产品核心由“二维码管理”调整为“快速登记和现实对应”。
2. 新增批量照片生成箱子草稿及连续编辑流程。
3. 新增语音转写生成默认箱子和备忘录流程。
4. 新增识别失败、权限拒绝和离线不可用的降级路径。
5. 新增实体箱体标记状态和强提醒机制。
6. 二维码补充高清单图、单个 PDF、A4 批量 PDF 和系统打印适配。
7. 新增无打印条件下的手写编号、便利贴和稍后打印兜底。
8. 明确“标签已导出”与“现实箱体已标记”是不同状态。
9. 明确二维码不保存完整物品和地址等敏感信息。
10. 明确产品全功能免费，无订阅、付费墙和广告依赖。
11. 保持项目、搜索、扫码、搬运状态、进度、导出和备份等原有核心功能不变。

## 17. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 用户仍觉得录入麻烦 | 放弃使用 | 自动编号、照片/语音建箱、非必填字段、批量操作 |
| 数字记录与现实箱体错位 | 搜索结果无效 | 待实体标记状态、强提醒、照片缩略图和箱号确认 |
| 用户没有打印机 | 无法使用二维码 | 手写编号、便利贴、放大箱号和稍后打印 |
| 语音识别错误 | 备注不准确 | 保存完整转写、结果可编辑、解析结果仅作建议 |
| 离线语音不可用 | 快速录入受阻 | 手动备注即时降级，其他核心能力保持离线 |
| 二维码损坏 | 无法扫码 | 标签同时显示可读箱号，可手动搜索 |
| 箱号修改导致旧标签不一致 | 现实映射错误 | QR 使用稳定 UUID；修改箱号时提示更新现实标签 |
| 批量流程中断 | 数据丢失 | 草稿逐项持久化，可恢复未完成批次 |
| 免费产品缺乏收入 | 后续维护压力 | 先验证真实使用价值；商业模式变更必须单独评估 |
| 功能扩张成仓储系统 | MVP 延期 | 严格遵守非目标和 P0/P1 边界 |
