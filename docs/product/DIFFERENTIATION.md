# ReaderEdit 差异化与原创性报告

评审日期：2026-09-30
门禁结论：`passed_with_risk`。这是产品内部门禁，不是 App Review 预测。

## 产品命题

ReaderEdit 是面向中英文独立小说作者的无账号离线工作区：用户先把整本小说或长文导入为本地章节，在阅读中随时修改；需要精修时，再把合适章节转入“读者信号 → 修订队列 → 前后对照 → 承诺复核”的结构化流程。

## 与参考产品的关系

新增书架、章节和长文导入后，ReaderEdit 与“作家助手”等写作产品在基础名词上出现合理重合：小说、章节、写作、阅读。这些是类别通用能力，不能再用“没有书架/章节树”作为差异证据。当前差异必须由以下可验证产品行为承担：

- 离线、无账号，导入后正文复制进本地原子工作区；不依赖平台作品、云端发布或社区关系。
- 阅读页与编辑页是同一章节状态，保存后立即回到阅读，不要求把长文反复粘贴进临时修订表单。
- 精修不是通用待办：冻结原稿后逐段记录清楚/拖沓/迷失，问题段自动进入队列，保留前后版本和读者承诺。
- 删除后的小说/章节/修订不会因恢复副本而复活；旧 revision-only 数据可迁移到同一工作区。

## 硬失败扫描

- 差异仅限名称、图标、颜色、语言或 Bundle ID：否；核心差异仍是读者信号状态机、队列来源、前后记录和本地恢复协议。
- 复刻单一竞品屏幕层级和主操作顺序：未发现；书架是原创暖纸编辑台布局，精修路径与发布/社区/收益路径不同。
- 使用竞品截图、品牌、素材、数据集或文案：未发现；示例、图标和文案均为本项目资产。
- 同一模板或代码库的低差异版本：未发现；当前目录不是 Git 仓库，无法提供历史级溯源，这一结论只基于受审文件。
- 登录、订阅、广告、社区或 AI 作为装饰增项：不适用。

## 防止产品漂移的边界

- 书架和编辑器是读者视角修订的输入与工作空间，不扩成社区、发布、粉丝、收益或内容平台。
- 不用泛用 AI 续写/润色代替作者判断；如未来加入，应有独立价值与数据披露。
- 新增重排、拆分、搜索、导出时优先加强“长文定位 → 阅读 → 修改 → 验证 → 恢复”的闭环。
- 章节正文变化不得静默重用旧段落信号；当前用独立冻结会话规避，未来若绑定/回写必须设计明确失效和冲突处理。
- 商店材料不能把通用书架当作主要差异，应展示导入后阅读编辑与 reader-signal 精修的连续路径。
